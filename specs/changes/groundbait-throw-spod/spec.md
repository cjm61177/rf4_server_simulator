# 手抛与打窝器扣料通道

Status: done

## Problem Statement

手抛 12/1 和打窝器 14/3 都会在客户端侧消耗窝料，但服务端此前没有接入扣料与窝账，
导致重登后数量复活，且打窝器落水后没有窝效。

## Solution

手抛请求由服务端真实扣一份并同步背包；打窝器在 14/3 入水信号扣料并写入 `spod` 通道。
两者都沿用落点三档与幂等键。

## User Stories

1. 作为玩家，我希望手抛窝料后数量不会在重登时复活。

2. 作为玩家，我希望打窝器入水后窝料真正计入落点。

3. 边界：重复上报不能重复扣料。

## Implementation Decisions

- 模块：`internal/gameserver` 的动态协议、钓鱼入水处理和窝料账本。

- 12/1：校验物品归属和品类后扣 1 份，推送 4/21 或 4/22，再写通道 `hand`。

- 14/3：打窝器族才触发 `consumeCastBait`，通道记 `spod`。

- 通道映射只作溯源，不影响吸引计算。

## Testing Decisions

- 行为：手抛扣料、数量同步、打窝器落水、通道映射和重复上报。

- 回滚后失败项：12/1 扣料、14/3 扣料和 `spod` 通道断言。

## Out of Scope

- 不新增客户端协议字段。

- 不改变弹弓落点和鱼口公式。
