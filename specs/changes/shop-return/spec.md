# 商店退货：凭据、原子退款与客户端规则

Status: done

## Problem Statement

钓鱼站、工业品、Beluga 和 Zeiman 商店的 22/4 退货不完整：购买凭据只依赖物品 origin 字段，服务端无法稳定按原店/币种/金额退款；重复请求或跨店退货可能重复退款；玩家重启后真实鱼竿的出厂装配投影会被误判为已装配；服务端也没有执行客户端已有的 48 小时时限和品类白名单。结果是正常退货失败，而构造请求可能退掉不可退商品或旧商品。

## Solution

购买与退货都保存可核验的批次凭据。22/4 在同一事务内校验原店、币种、金额、购买时间、商品状态、品类白名单和装配状态，成功后扣物、退款并保存回执；相同请求幂等，非法请求回滚。真实鱼竿允许启动回填产生的出厂装配投影，但拒绝玩家后加的组件，并清理退货鱼竿的 rig/rod_setting 派生数据。

## User Stories

1. 作为钓鱼站/工业品/Beluga/Zeiman 商店玩家，我可以用银币或金币按原购买批次退货，退款金额和币种正确。
2. 作为刚购买鱼竿的玩家，服务端重启后未使用、未改装的鱼竿仍然可以退货。
3. 作为误发重复退货请求的玩家，重复请求回复同一结果，不会重复退款或重复扣物。
4. 边界：超过 48 小时、不可退品类、已使用/已修改/已装配/跨店/非本人商品均拒绝，商品和钱包不变。

## Implementation Decisions

- `internal/gameserver/shop.go`：购买事务保存批次凭据；商店购买按批次独立入库，避免退一件商品删除原有堆叠。
- `internal/gameserver/shop_return.go`：22/4 使用事务和请求回执；凭据记录原店、item_id、币种、金额、购买游戏分钟和完整物品批次。
- 退款校验：当前游戏分钟与购买游戏分钟差达到 69120 时返回原生 149；品类白名单同步客户端 `fbankbpbdbf.pfnbedifjcm`；`hgaijieklek` 的 0x800000 位拒绝退货。
- 鱼竿装配：以购买时 f5/f3/f4 快照计算出厂组件，只拒绝玩家后加的 rig_component；退货时清理 rig_component、rig 和 rod_setting。
- 失败语义：不在背包返回 111，非全新货返回 150，仍有装配关系返回 151，其余事务/凭据失败返回 196。
- `cmd/gameserver/main.go`：启动时恢复可唯一对应的旧购买凭据；无法证明原数量/状态的旧堆叠、套盒和已使用件不恢复。
- 无表结构迁移；旧库由启动恢复逻辑兼容。回滚方式为 revert 本 PR。客户端基线为 4.0.25034。

## Testing Decisions

- 行为/存储层（真实 SQLite）：四家商店、银币/金币、重连、请求回执幂等、跨店/非本人、已使用/已修改/已装配/容器变化、钱包/扣物失败回滚。
- 规则层：48 小时边界、品类白名单、不可退状态位。
- 装配层：真实 `boatr_10213_012` 鱼竿购买后执行 `BackfillRigProjections`，出厂投影可退且清理 rig/rod_setting；玩家加装 rig_component 返回 151。
- 回滚后上述测试会变红，尤其是时限、不可退品类和出厂鱼竿退货。
- 门禁：`go test ./... -count=1`、`go vet ./...`、`go build ./...`。

## Out of Scope

- 不新增商店、不改变售价、库存或折扣规则。
- 不恢复无法证明完整状态的旧套盒/旧堆叠凭据。
- 不改变 22/2、22/3 的购买协议响应形状。
