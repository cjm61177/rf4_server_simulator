# 自制引线进入钓组承力链

Status: done

## Problem Statement

玩家用自选线材和连接件做的引线（成品引线）比主线更弱时，搏鱼本该先断这根引线，
服务端却把断件判到主线、鱼竿或渔轮上：客户端已经提示断引线，背包里钓组却显示
一切正常，玩家还能继续作钓，之后进工坊改装鱼轮会报内部错误。同一根引线下一次
磨损也不体现：客户端看到的仍是制作时写好的强度。

## Solution

自制引线和商店成品前导一样参与最弱环判定：服务端按引线实例上实际装配的线材与
连接件计算承力，取两者较小值，再按引线当前耐久打折。客户端上报断引线时服务端
断的就是这根引线；下发给客户端的引线强度与服务端用的是同一个数，磨损实时生效。

## User Stories

1. 作为玩家，我希望引线比主线弱时先断引线，以便损失落在便宜的那一件上。
2. 作为玩家，我希望引线磨损后强度实时下降，以便提前换线而不是满红硬拉大鱼。
3. 边界：引线耐久已耗尽时不把强度强行写成 0，保持"损坏件等客户端上报"的既有行为。
4. 边界：商店成品前导的定义自带内嵌线材与连接件数值，仍按定义取值，行为不变。
5. 边界：竿实例的钓组对象与派生装配索引只有一处有引线记录时，断件裁决与承力链
   必须看到同一根引线，不能一个看得见一个看不见。

## Implementation Decisions

- `internal/gameserver/gear_physics.go`：装配快照读定义拿不到引线承力时（自制引线的
  内嵌线材 `mbnambppbom` 与连接件 `lbadjgllglo` 都是 null、顶层也没有 `kngaaefkpka`），
  读取引线实例内嵌材料的 `nlmnpekipjc`，取最弱值作为基准承力，再按引线实例耐久
  结算。该字段由制作/修复路径按“真实材料额定拉力 × 材料自身耐久 × 材料工艺”写入；
  普通主线映射到前导线模型时，不能按模型 `numeric_id` 回查定义替代它。旧存档缺少
  该字段时，才按内嵌材料定义与内嵌耐久/工艺回算。装配解析同时输出引线 GUID，
  供断件裁决复用。
- `internal/gameserver/gear_damage.go`：断件裁决的引线 GUID 与承力链同源，优先竿实例
  的钓组对象，回退派生装配索引，品类优先前导线（15）再子线（13）。
- `internal/gameserver/items.go`：物品下发时自制引线按同一口径重算受力上限并乘当前
  耐久；耐久为 0 时不改写，保留"损坏件不强写 0"。
- 数据与迁移：不改表结构、不改协议字段，存量存档在下次下发时自动修正。
- 兼容：客户端基线保持 `4.0.25034`；回滚方式为 revert 本 PR 的功能提交。

## Testing Decisions

- 接缝：行为 + 真实 SQLite。用真实制作流程产出成品引线（线材 3.4kg、连接件 6.75kg），
  装配到合成竿/轮/主线，断承力链取值、最弱环、断件裁决和下发强度。
- 期望值来自线材与连接件定义的额定拉力以及制作流程的既有断言，不用本实现反算。
- 覆盖非 1 材料耐久/工艺、普通主线写入 f3，以及映射模型 `numeric_id` 与真实材料
  强度不同时仍以嵌套 `nlmnpekipjc` 为准。
- 覆盖耐久减半时“制作快照强度 = 服务端承力 = 下发客户端强度”同步减半，防止两端
  各算一套。
- 回滚后 `TestCraftedLeaderEntersStrengthChain` 会变红：引线承力回到 0、最弱环回到主线、
  空上报的断件裁决不再指向该引线。

## Out of Scope

- 不调整鱼种分布、咬钩概率、派鱼重量上限和经济价格。
- 不处理泄力打滑与摩擦片耐久的消耗路径，那是另一条独立链路。
- 不改客户端协议字段与数据库表结构。

## Further Notes

- `[事实]` 自制引线的定义里内嵌线材与连接件属性都是 null：材料与连接件是玩家制作时
  才选定的，只有物品实例上才有，读定义必然得到 0。
- `[事实]` 实机日志里客户端上报自制引线断裂（实例强度低于主线与鱼竿），服务端裁决
  的却是渔轮，日志中的引线承力为 0。
- `[事实]` 路亚拟饵的出厂钩没有独立物品行，断件上报为空或 zero GUID，此时服务端走
  最弱环回退裁决，引线看不见就会断错件。
- `[推断]` 下发链路此前对自制引线不写强度字段，客户端一直使用制作时写进快照的旧值，
  所以磨损不体现。
