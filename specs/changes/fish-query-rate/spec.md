# 查鱼理论发鱼速率

Status: done

## Problem Statement

单次判鱼概率不能表达不同饵料和钓法的服务端发鱼节奏，更不能当成实际鱼获频率。

## Solution

以单次目标鱼概率除以平均判鱼间隔，折算每分钟及每小时期望；按理论条/小时排序并显示，明确不含客户端等待、非实际鱼获。

## User Stories

- 玩家可比较同张地图不同区域、饵料及钓法的理论速率。
- 固定间隔或水域覆盖生效后，下一次查询读取同一套参数。

## Implementation Decisions

- 保留原有概率字段，增加平均间隔、每分钟及每小时理论期望；不改变消息协议形状。
- 普通竿对生产离散间隔逐个变换后平均；路亚对截断后的均匀短窗分段积分。不使用随机抽样，不改变真实发鱼分布。
- 复用生产配置优先级、天气和技能、先限幅后倍率的顺序；无饵区域粗筛仍不含时延，精算按速率排序。
- 上游档位比例与查询共用可用档位参数，保留整数克舍入、装备截断及幸运加成；无可用档位时沿用上游回退。
- 单竿、单饵、无窝料；不含客户端等待、占竿、搏鱼、收鱼、重抛及落水就位保护。当前条件固定折算，不预测未来一小时。

## Testing Decisions

手算间隔、截断次序、路亚积分、固定/水域覆盖、单位换算、低概率高速率排序、档位比例与采样对照；只读及不消费生产随机数回归。完整 Go test/vet/build。

## Out of Scope

客户端鱼口模型、实际鱼获统计、改变发鱼行为、自动部署或推送。
