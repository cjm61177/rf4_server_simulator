# 查鱼鱼名拼音前缀匹配

Status: done

## Problem Statement

玩家输入鱼名的开头或同音字时，现有名称查询可能无法识别，也可能要求从多个候选中重新选择。为每条鱼维护简称表会增加资料维护成本。

## Solution

完整鱼名和鱼种编号仍可查询；其他输入与鱼名统一转为无声调拼音，按前缀匹配。多个候选直接选择鱼种编号排序的第一种，回复使用完整鱼名，不增加确认步骤。

## User Stories

1. 玩家输入“圆腹”“元腹”或“yuanfu”，即可查询圆腹雅罗鱼，无需输入完整名称。
2. 多个鱼种符合前缀时直接查询第一种，玩家可从回复标题确认实际查询的鱼种。
3. 未找到鱼种时仍给出提示；地图名称及“鱼名 [地图]”指令格式不变。

## Implementation Decisions

- 仅修改 `internal/gameserver` 的查鱼名称解析及帮助文本，精确鱼名和编号优先于拼音前缀。前缀候选按 `fish_key` 固定排序，不受资料插入顺序影响。
- 使用 [go-pinyin v0.21.0](https://github.com/mozillazg/go-pinyin/tree/v0.21.0) 的无声调转换，采用默认单一读音，不展开多音字组合。该依赖为 MIT 许可，无额外模块依赖；许可证保留在 `docs/licenses/go-pinyin-LICENSE`。
- 输入和资料名清理首尾空白及 BOM，拉丁字母忽略大小写；未识别字符原样保留，空输入不匹配任何鱼。重复鱼名行不构成歧义，也不修改静态资料。
- 沿用现有个人消息响应形状及查询预算，不改概率、排名、表结构、迁移、权限或客户端文件。客户端基线仍为 `4.0.25034`。
- 回滚只需更换程序，无存档转换；已保存的文本回复不重写。

## Testing Decisions

- SQLite 接缝测试使用字面量输入/期望鱼种，覆盖中文前缀、同音字、完整拼音、大小写、编号、精确名称优先、多个候选首条及重复隐藏字符名称。
- 回归空输入、标点、首字母缩写和鱼名中间片段不被当作有效前缀；取消/超时沿用现有测试。
- 回复测试覆盖前缀查询仍显示完整名称、可选地图仍有效、帮助保留等待说明且不恢复档位指令。
- 回滚名称解析后，同音字、拼音及首候选测试应失败；测试期望值不通过同一转换函数计算。
- 完成后执行查鱼专项及完整 `go test ./...`、`go vet ./...`、`go build ./...`。自动测试不替代部署后的实机验收。

## Out of Scope

简称/别名表、编辑距离纠错、拼音首字母缩写、歧义选择菜单、地图名模糊匹配、生产发鱼规则和服务部署。
