# 窝料按实际用料计算食性

Status: done

## Problem Statement

自制窝料在客户端都叫 `feedcompleted`，只看 item_id 无法区分玉米配方和红虫配方。
装填或挂饵拆出子实例后，如果配方不随实例复制，投放时还会退回通用档案。

## Solution

制作时记录实际用料，装填/挂饵拆实例时复制配方；投放时冻结进窝账并按食性向量现算逐鱼种亲和。

## User Stories

1. 作为玩家，我希望不同配方吸引不同食性鱼种。

2. 作为玩家，我希望装填到弹弓或挂到食笼后仍使用原配方。

3. 边界：实例被消耗后，已投放的窝仍保留当时用料。

4. 边界：攻略表不可用时退回预烘亲和表。

## Implementation Decisions

- 模块：`internal/gameserver` 的制作、装配、投放和判鱼权重。

- 数据：新增 `groundbait_recipe` 与账本 `materials_json`。

- 原料按基底/添加剂/香精权重合成食性向量。

- 攻略吃饵表与生态食性按双票打折；专食性要求明显主力食性。

- 子实例 GUID 必须获得同一份配方映射。

## Testing Decisions

- 单元：原料合成、运行时亲和、专食性、掠食冻结。

- 行为：自制配方分化、装填/挂饵子实例配方继承、弹弓账本冻结用料。

- 回滚后失败项：运行时亲和、配方分化与实例用料断言。

## Out of Scope

- 不处理 PVA 水溶网载体语义。

- 不改客户端物品名称体系。
