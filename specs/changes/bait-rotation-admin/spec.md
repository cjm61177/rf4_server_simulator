# 后台鱼饵规则编辑与定时轮换

Status: done

## Problem Statement

鱼饵偏好规则和 companion 实证只能在服务端文件中查看，运营无法在后台定位“某鱼为什么不吃某饵”，
也无法按时间段让同一鱼种轮换使用不同饵组。

## Solution

后台「鱼饵偏好」可覆盖每个鱼种的吃/不吃/底钓只吃/前置条件，并配置软性或严格的多组定时轮换；
覆盖写入玩家库，判鱼优先读取覆盖，未覆盖或停用时回落到内置规则。轮换按时间桶计算，后台展示与判鱼同源。

## User Stories

1. 作为运营，我希望在后台编辑鱼饵规则，不必修改并重启服务端。
2. 作为玩家，我希望同一鱼种可以按时间轮换饵组；严格模式只认当前组，软性模式组外饵降权但仍可咬。
3. 边界：只配置 0/1 组、未填间隔或间隔小于 60 秒时，不启用轮换，后台不显示虚假的“下次切换”。
4. 边界：后台保存后最多 30 秒内影响判鱼；关闭规则总开关时不生效。

## Implementation Decisions

- 存储：新增 `fish_bait_override` 表和仓储，保存覆盖规则、轮换组、间隔、模式与启用位；迁移 `00052_fish_bait_override.sql`。
- 判鱼：`resolveBaitRule` 优先后台覆盖，缓存 TTL 15 秒，保存后主动失效；无覆盖/停用回落内置规则。
- 轮换：`floor(unix/interval) % group_count` 计算当前组；`group_count <= 1`、间隔小于 60 秒均视为未启用。
- 模式：soft 当前组 ×3、组外 ×0.5；strict 只放行当前组。
- 后台：新增规则保存/恢复默认、饵料分类与物品清单接口；编辑器先选分类再选饵，保存前校验最多 20 组。
- UI：鱼饵编辑器关闭/按 Esc/点遮罩时，若有未保存修改先确认；保存或恢复默认后可强制关闭。
- 兼容：客户端基线 4.0.25034；无协议改动。回滚：删除覆盖表与后台路由，判鱼回落到内置规则。

## Testing Decisions

- 单元/存储（真实 SQLite）：覆盖保存/读取/恢复默认、同鱼种去重清洗、轮换参数上下限。
- 行为（gameserver）：覆盖优先级、停用回落、时间桶切换、soft/strict 权重；单组和无间隔不启用。
- 后台 API：保存后 `/api/bait/prefs` 与 `/api/fish/config` 同步返回轮换状态。
- 浏览器 smoke（Playwright）：真实打开后台鱼饵页，打开编辑器、添加第二组、打开饵料分类选择器、编辑未保存状态关闭时必须出现确认。
- 回滚后：轮换开关与编辑器未保存确认测试会变红。

## Out of Scope

- 不改 companion 实证数据本身，不改窝料 affinity。
- 不追溯修改已入护渔获的饵料快照。
- 不新增官服未证实的轮换概率或时长。

## Further Notes

- [事实] 后台展示与判鱼必须共用 `gameserver.ExportedRotationState`，否则会出现“页面显示组 2、实际按组 1 判鱼”。
- [事实] 规则总开关关闭时覆盖仍保存在库中，但判鱼不读取。
- [推断] 软性模式 ×3/×0.5 是本地体验参数，不代表官服。
