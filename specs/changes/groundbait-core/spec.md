# 窝料基础账本与食性吸引

Status: done

## Problem Statement

窝料此前没有服务端账本，无法表达“在哪个格子投了多少份、还剩多久、是否过量”。
玩家的投放也不会稳定影响鱼种权重，自制窝料和商品窝料无法按同一套规则参与判鱼。

## Solution

按玩家、钓点、5 米网格和批次记录窝料投放。每份窝料提供固定在线游戏时长，
在有效期内按鱼种食性提高对口鱼权重；过量投放压低开口率，鱼吃口和时间流逝会逐步消耗账本。
食笼、PVA 与弹弓在入水时把实际消耗的窝料写入账本。

## User Stories

1. 作为玩家，我希望在一个落点投窝后，对口鱼种更容易咬钩。
2. 作为玩家，我希望过量投喂会让鱼口变差，而不是无限叠加收益。
3. 作为玩家，我希望窝料只在在线游戏时间内衰减，断线期间暂停。
4. 边界：重复上报同一投掷不能重复记账。
5. 边界：总开关关闭时，原有判鱼流程必须保持不变。

## Implementation Decisions

- 模块：`internal/gameserver` 的判鱼权重、咬钩闸门、饵料入水消耗与动态协议处理。
- 数据：新增 `groundbait_deposit` 和 `groundbait_clock` 玩家表。
- 记账维度：玩家、钓点、5 米网格、投放通道和幂等键。
- 在线钟：会话 keepalive 持续推进，业务请求补算；单次跨度封顶 30 秒，避免长期离线补时。
- 幂等：弹弓幂等键包含手持物 GUID、网关会话号和 CallID，跨登录复用 CallID 不冲突。
- 兼容：总开关 `groundbait_enabled` 缺省关闭；客户端基线 4.0.25034。

## Testing Decisions

- 单元：份数时效、过量曲线、食性亲和、天气软化和掠食者冻结。
- 存储：真实 SQLite 验证玩家表登记与迁移。
- 行为：弹弓和食笼/PVA 入水后只记账一次；同 CallID 跨会话仍能分别记账。
- 时间：keepalive 推进在线窝料钟，长时间没有判鱼也不会丢掉在线时间。
- 回滚后失败项：在线钟推进、跨会话幂等和基础窝料权重测试。

## Out of Scope

- 不自制窝料实例用料，不处理 PVA 填充比例。
- 不新增手抛和打窝器专用通道。
- 不修改客户端原生抛饵动画。

## Further Notes

- [事实] 客户端基线 4.0.25034 已确认食笼/PVA 和弹弓入水扣料链路。
- [推断] 份数、时长和过量阈值为服务端玩法标定值，可通过 tunable 调整。
