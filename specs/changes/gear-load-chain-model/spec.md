# 承力件断件链与渔轮泄力模型

Status: done

## Problem Statement

玩家在搏鱼时，钓组会错误地只比较竿、主线和子线，铅芯前导、连接件和钩没有进入承力链；同强度或更弱的这些部件无法按其真实拉力断裂。渔轮又把当前泄力档位当成最弱承力件，导致低档位频繁被判“渔轮损坏”，但背包里的轮子耐久并未归零，出现提示损坏与物品状态不一致，鱼也无法正常通过泄力打滑逃窜。

## Solution

搏鱼超载时，服务端按真实装配逐件比较竿、主线、前导/子线、铅芯前导、连接件和钩的当前拉力，决定实际断件；30 档锁轮时锁轮承力参与比较。1~29 档泄力打滑只磨损摩擦片并让鱼借线逃窜；摩擦片磨穿后泄力失效，本体仍可到工坊换片。断子线、连接件或铅芯时只删除该位置以下的终端件，不误删主线上游组件。

## User Stories

1. 作为玩家，我希望弱钩、弱线、弱前导、铅芯或连接件都能按真实最弱环断裂，以便装配选择与搏鱼结果一致。
2. 作为玩家，我希望泄力打滑表现为鱼逃窜和摩擦片磨损，而不是错误提示整个渔轮损坏。
3. 作为玩家，我希望摩擦片磨穿后泄力归零、需要换片，但轮子本体和已装配状态仍保留。
4. 边界：客户端上报的断件与物理最弱环不一致时，以服务端裁决为准；只有拟饵、饵和浮漂等不承力终端件可直接采信。
5. 边界：旧存档里的摩擦片字段缺失时按额定值初始化；已持久化的 `0` 必须继续表示磨穿，不能重新满血。

## Implementation Decisions

- `internal/gameserver/gear_physics.go`：装配快照纳入竿、主线、前导/子线、铅芯前导、连接件、钩与锁轮承力；同强度时优先断下游便宜件。
- `internal/gameserver/gear_damage.go`：`17/9` 先校验上报件属于当前钓组，再按最弱环裁决；泄力打滑与锁轮超载走两条独立损坏通道；下游丢失集合按 `rigSlotTemplates` 中的断件位置计算。
- `internal/gameserver/reel_performance.go`、`items.go`、`item_repair.go`、`reel_repair.go`：摩擦片制动力 `csDragForce` 作为持久化磨损状态，物品树下发、启动修复和零件重建都不得覆盖已存在的值。
- 数据与迁移：不新增表结构；使用既有 KV 标记执行一次性存量零值迁移，迁移可重复运行且只在标记缺失时执行。
- 兼容：客户端基线保持 `4.0.25034`；旧轮缺少摩擦片字段时补额定值，已有 `0` 保持磨穿；回滚方式为 revert 本 PR 的功能提交。

## Testing Decisions

- 存储与行为测试使用真实 SQLite 和仓库静态道具定义，覆盖摩擦片单次磨损、磨穿后再次打滑、`ItemToTree`、启动修复、零件重建和一次性迁移。
- 协议与装配测试覆盖真实装配铅芯前导的 `17/9` 上报、强钩弱线反向裁决，以及子线/连接件/铅芯断裂的下游丢失集合。
- 期望值来自道具定义的额定拉力、手算磨损步进和真实装配槽位关系，不用同一实现反算结果。
- 回滚后摩擦片复活、物品树回满、铅芯上报被拒、强钩弱线误判和上游铅芯误删等测试会重新变红。

## Out of Scope

- 不调整鱼种分布、咬钩概率、抛投距离公式或经济价格。
- 不新增客户端协议字段，不改数据库表结构。
- 不追求复刻官方未公开的全部耐久数值，只保证当前装配数据上的行为自洽。

## Further Notes

- `[事实]` 客户端会通过 `17/9` 上报钓组超载及断件；服务端必须再校验装配归属和实际最弱环。
- `[事实]` 摩擦片、导环等零件是装配件，本体损坏位与摩擦片磨损是不同状态。
- `[推断]` 现有真实道具的拉力字段足以支撑逐件最弱环判定；缺字段时仍保留兼容回退。
