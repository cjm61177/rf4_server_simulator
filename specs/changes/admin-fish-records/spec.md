# 管理后台编辑个人鱼种记录

Status: done

## Problem Statement

本地游玩的玩家需要恢复官服已达成的鱼种记录，现有管理后台只能添加护网鱼，不能补录图鉴。

## Solution

在玩家管理增加“鱼种记录”页签，按地图搜索鱼种，补录已钓获、达标、星、蓝冠，可选填真实重量，留空时采用该档位最低重量。保存前在线备份，重复保存替换该地图鱼种的工具补录，实钓纪录保留。

## User Stories

- 管理员在原有登录后为已下线的指定玩家补录记录，玩家重新登录游戏后查看图鉴。
- 管理员可以清除工具补录；同鱼种的实钓记录保留。
- 档位与重量不匹配、鱼种不属于地图、备份失败时不修改记录。

## Implementation Decisions

- admin 增加受既有认证保护的 GET/POST `/api/players/records`，沿用玩家管理界面。
- gameserver 复用实际发鱼/结算档位尺和体长公式准备记录；不改变游戏协议形状。
- store 使用现有 catch_log，不迁移表。新来源为 `admin_record_restore`，兼容原工具的 `official_restore_console`。
- 写入前使用 SQLite backup API 备份主库，补录和审计在一个事务内。静态库只读。
- 补录不发奖励、不加护网或资产；每条补录计入一次钓获统计，不能恢复官服完整次数与时间历史。
- 回滚程序后补录仍能由既有图鉴读取；取消补录只删除工具来源行。

## Testing Decisions

- 临时 SQLite 库验证受认证的管理 API、地图校验、重复保存不叠加、实钓与其他玩家保留、备份包含 WAL 中已提交数据。
- gameserver 验证实际档位尺及补录进入既有图鉴生成函数；不新增协议字段。
- 构建后查看玩家管理的新页签，不向真实存档添加测试鱼。

验证：Go 完整测试、vet、build 通过；本地后台已验证地图名册、档位与重量输入加载。目标玩家下线时补录及重新登录后的图鉴显示已由玩家验证正常。在线仅做过少量未崩溃测试，未完整验证即时刷新、并发编辑与持续实钓；建议玩家下线后补录。

## Out of Scope

不抓取官服账号数据，不恢复不存在的历史明细，不重复实现货币或物品管理。
