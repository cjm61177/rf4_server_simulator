# 一次挖饵产出多种饵

Status: done

## Problem Statement

挖饵（9/3，铲子/红虫长柄勺）原来每次只产出一种饵，无法体现一次翻土出现多种饵的体验。
“挖到某饵”的成就也只按单件产出判定；改为多件后，如果仍只上报首件，会导致同次产出的其他饵漏判成就。

## Solution

一次成功挖饵按熟练度权重表抽取 1-3 种不重复饵，每种独立 1-3 个；803.f1 展示本次全部产出，
每种饵各推一条背包增量，并对实际产出的每种饵分别触发挖饵成就事件。

## User Stories

1. 作为玩家，我希望一次挖饵可能翻出 1-3 种不同饵，以便采集过程更接近游戏体验。
2. 边界：同一次挖饵不会产出重复饵种；熟练度不足 40 时不会出第 3 种。
3. 边界：精力不足或任一物品入包失败时，不扣精力、不产出任何饵。
4. 边界：同次产出多种饵时，每种符合条件的“挖到某饵”成就都应被判定。

## Implementation Decisions

- 模块：`internal/gameserver/baitdig.go`，沿用 `baitDigBands` 权重表和既有经济事务。
- 掉落：先按熟练度选档，再按权重无放回抽取 1-3 种；每种数量沿用原 1-3 个规则。
- 事务：精力扣减、逐种入包和流水写入仍在同一事务内；失败整体回滚。
- 响应/推送：803.f1 为本次获得预览数组，803.f6/f7 为背包堆快照；每种产出单独推 4/22。
- 成就：事务提交且响应构造成功后，对实际产出的 `keys` 逐种调用 `evaluateAchievements`。
- 兼容：客户端基线 4.0.25034；803.f1 客户端按对象数组消费，`aedpdgpbcho` 对其枚举并交给物品快照入口，静态反编译支持多项。
- 回滚：回退本 PR 即恢复单种产出；无表结构迁移。

## Testing Decisions

- 单元：固定 RNG 扫描 500 个种子，校验种类数 1-3、饵种不重复、数量 1-3、产出均在当前档位表内。
- 单元：固定 RNG 验证熟练度 40 门槛与概率边界。
- 行为：handler 级验证多物品入包、803.f1/f6/f7 数量、逐件 4/22 推送和堆 GUID 稳定。
- 行为：使用长柄勺成功挖饵后，按实际产出的饵种检查对应成就（250/258/259/261/272）已解锁。
- 回滚后：多饵与逐种成就测试会变红，原有单饵入包测试保持绿。

## Out of Scope

- 不改熟练度成长数值、精力消耗和工具耐久。
- 不改饵料掉落权重表的具体数值。
- 不做实时客户端画面验证；仅以 4.0.25034 客户端反编译消费链和协议数组形状作为兼容依据。
