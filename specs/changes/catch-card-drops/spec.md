# 钓获掉卡

Status: done

## Problem Statement

卡片定义与收藏已可读取，需要给实际钓获增加单机掉卡规则，保证重放、重连不重复发卡。

## Solution

收竿成功结算时，按实际鱼档位抽取对应鱼种的一张卡，与经验、磨损及钓获回执放在同一事务提交；通过 801 获得物品列表显示本次卡片，并同步收藏库存。

## User Stories

- 普通、达标鱼默认 0.1%，星 50%，蓝冠 80%；稀有与超稀有鱼再乘 0.25。
- 后台游戏参数可以调整四个数值，沿用参数缓存，最多 30 秒生效。
- 入护或放生都保留已钓到的卡，跑鱼、主动脱钩、补录图鉴不发卡。

## Implementation Decisions

- 规则为用户指定的本地玩法，不代表官服概率；鱼饵和天气通过发鱼规则影响鱼种和档位，不额外改变掉卡条件。
- 静态定义按 okppoalfakf 找对应卡片，不存在定义时不掉卡。
- uid + 鱼 GUID 的稳定哈希提供一次抽取值；相同鱼的重试沿用同一抽取值。
- 卡片携带原鱼 GUID、鱼种、重量、档位、地图与饵料信息；库存独立实例 GUID，与原鱼不同。
- 物品 INSERT 和 catch-settlement 回执在同一事务；旧回执不补抽、不补发。
- 客户端 4.0.25034：proto.ps1 核对 14/4 为 801，客户端结算基类的 iingicaldbk 是新增物品数组，对应 801.f8；用 args(61,item)，卡片为已有 11301 类型。不新增命令或字段。
- 重放时仍读取原卡片，已入册的卡片不重新加入散卡库存；无掉卡时返回空物品数组。

## Testing Decisions

- 校验默认概率、稀有折扣和参数覆盖。
- 临时 SQLite 验证同鱼重复/重启结算只发一张、不同鱼 GUID 独立、事务失败无残留，以及卡片保留实际鱼资料。
- 完整 Go test/vet/build 与后台脚本语法检查；客户端实测核对掉卡动画和收藏库存。
- 14/4 协议回环验证本次掉卡在 801.f8 出现，与落库实例相同；重复结算及入册后重试都不再发卡。

验证：完整 Go test/vet/build、后台脚本语法检查通过；默认概率、参数覆盖、重启重放、不同鱼 GUID、事务回滚与原鱼资料均在临时库验证。玩家已确认掉卡动画和收藏库存显示，入册、取回与重登亦已通过；未用实机样本统计概率。

## Out of Scope

不做卡册奖励、交易、覆膜、资格任务，不推送未经用户验证的提交。
