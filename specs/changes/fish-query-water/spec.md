# 查鱼区域离线水陆粗筛

Status: done

## Problem Statement

纸地图与地形边界裁剪仍会推荐明显陆地区域。需要低成本的水陆粗筛，不改变实际发鱼及概率计算。

## Solution

离线读取用户本地客户端的地形高度及水体数值信息，预处理每个裁剪后40米格子的中心与四角。任一点落在候选水体范围内且地形低于基准水面即保留；五点均非水则剔除。服务端仅加载预生成表，在无饵区域粗筛前过滤。

## User Stories

1. 无需启动、登录或注入客户端即可预处理并保存数据。
2. 后续查鱼直接查表，不在每次查询时读取客户端资源。
3. 混合水岸格允许保留；不保证格内每一点是水，不处理窄河漏检及精确可达性。
4. 没有有效数据时不能宣称已排除陆地；格式、范围不匹配的数据不能错套到其他格子。

## Implementation Decisions

- 独立Python预处理工具依赖UnityPy 1.25.4（MIT）及NumPy，仅为可选离线工具，不引入Go运行依赖。不复制第三方实现，来源与安装方式写入工具说明。
- 复用源码已有场景原点、纸地图裁剪和世界网格定义。地形按世界原点加高度采样；重叠地形采用最高表面，避免把群岛陆地误判为外层水下地形。
- 水体按已识别的水面组件、触发范围及适用的平面网格判断；只输出五点标记，不导出图片、网格、完整高度图或客户端文件。动态水面候选需有场景控制器引用，不能把无关停用对象视为水。
- 生成文件保存在用户本地；官方派生数据不随仓库或PR分发。自动测试只用合成数据。
- 数据表版本、取样规则、40米格子、场景范围和尺寸必须匹配。缺数据保持原查询，以 `WaterFiltered=false` 和 `Notes` 记录未做水陆粗筛；游戏帮助统一说明这一规则。已提供但损坏/不匹配的数据仍返回清楚错误，不静默伪装过滤成功。
- 原area编号、分布权重、饵料比较、生产发鱼及玩家库均不变。只影响内陆自动区域推荐，不拦截手动坐标或海图查询。
- 数据在进程内缓存，替换文件后重启游戏服务加载；部署必须另行安排，不因生成数据自动重启或启动客户端。

## Testing Decisions

- Python合成数据：五点任一为水、五点皆陆、裁剪/负原点、插值与地形叠层、水体平面网格覆盖。
- Go：文件解析、非法格式/尺寸/标记/范围、缺数据、过滤发生在粗筛前、原area及概率保持、全陆空结果、只读及原查询回归。
- 离线对实际本地地图逐图生成，记录保留/剔除数及无法支持的地图；核对亚马河和铜湖查询结果属于保留格。不把离线复算称为实机验收。
- 完整执行 `go test ./...`、`go vet ./...`、`go build ./...`，并运行Python单元测试。

## Out of Scope

动态波浪、潮汐、精确岸线、完整碰撞模拟、建筑/石头/桥梁阻挡、可达抛距、全格必为水、官服概率和自动部署。

## Verification

- Python六项合成测试通过；Go查鱼专项和完整 `go test ./... -count=1 -timeout=180s`、`go vet ./...`、`go build ./...` 通过。完整测试初次被沙箱的本机回环网络限制阻断，获准重跑后通过。
- 当前客户端的17张支持内陆图均完成离线生成；逐图加载核对数据范围与Go网格一致。亚马河大马哈鱼、铜湖圆腹雅罗鱼的只读查询结果均位于保留格内。
- 未启动游戏、未部署或重启运行服务；尚无本轮水陆过滤的实机验收。用法、依赖许可、数据本地保留及近似边界见 `docs/fish-query-water.md`。
