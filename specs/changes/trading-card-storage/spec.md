# 收藏卡库存同步

Status: done

## Problem Statement

钓获会播放掉卡动画，但收藏卡和卡册页面为空，玩家无法查看或整理已有卡片。

## Solution

卡片和卡册使用客户端的专用收藏库存；现有卡片保留原实例与钓获信息，升级后可读取。

## User Stories

- 钓获的新卡在收藏卡页面出现，可入册、取回，重登后仍存在。
- 旧存档中放在普通背包的卡片转入收藏库存，不增加卡片数量。
- 入册、取回和重复结算沿用原事务及幂等回执，不重复发卡。

## Implementation Decisions

- 客户端基线 4.0.25034，收藏卡面板实际绑定的库存模型使用 StorageType 18。
- `proto.ps1` 核对 4/5 的物品数组、11301 与 11304 的 StorageType 字段；保持现有响应形状与合同。
- 创建、掉卡、入册、取回及孤立卡片恢复统一使用 `native:18`；物品 StorageType 同步为 18。
- 已入册卡片在数据库中使用card_deck归属，wire仍为StorageType 18并保留父卡册GUID；收藏库存的数量、GUID分页和详情必须包含这些原卡，不能只返回散卡和卡册。
- 玩家库迁移只搬移普通背包中已知卡片/卡册实例，清理其快捷栏映射，保留字段、GUID、鱼资料和已入册卡片。
- 迁移在事务中执行，可重试；部署前备份玩家库。回滚需恢复部署前玩家库与程序。

## Testing Decisions

- 库存协议回环确认 18 能读到卡片及卡册，0 不再返回，StorageType 字面量为 18。
- 真实 SQLite 验证旧库升级、重复迁移和失败回滚，原鱼资料字节不变。
- 沿用掉卡幂等、入册取回、删除卡册恢复原卡的测试，更新库存预期。
- 完整 Go test/vet/build；实机掉卡显示和入册由玩家验收。

验证：库存协议回环、迁移回滚、掉卡及卡册测试通过；完整 Go test/vet/build 通过。玩家已确认收藏卡显示，并在最终修正版完成已有卡位、取回、再次入册和重新登录验收。

## Out of Scope

不补发卡片，不改变概率，不实现卡册奖励、覆膜或资格任务。
