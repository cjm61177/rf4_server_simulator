# 欢乐时光跟随会员：307.f24 状态映射

Status: done

## Problem Statement

欢乐时光资格改为跟随会员后，主页资料页的欢乐时光状态块（307.f24）与真实玩法不一致：

1. 管理员在后台关闭欢乐时光总开关（`happy_hour_enabled=0`）后，加成确实停止，但资料页仍显示"进行中"并在倒计时，玩家会误以为加成仍然生效。
2. 永久会员被下发 9999 真实分钟的倒计时（约 6.94 天），资料页显示"剩余 9999 分钟"而不是"不限时长"，到期时间一到还会显示"已结束"，与永久会员的实际权益矛盾。
3. 该改动修改了 307.f24 的字段语义，但没有变更说明，评审无法核对客户端倒计时公式、永久会员表示方式与回滚方案。

## Solution

资料页的欢乐时光状态按"是否有资格、总开关是否开启、会员是否永久"三件事决定：

- 非会员：显示"需要高级会员订阅"，不显示任何倒计时。
- 限时会员且总开关开启：显示"进行中"，倒计时等于会员剩余时长。
- 永久会员且总开关开启：显示"就绪"，不显示倒计时（永久生效）。
- 有资格但总开关关闭：显示"已结束"，不显示倒计时。

加成结算逻辑不变，只影响客户端展示。

## User Stories

1. 作为永久会员，我希望资料页不再显示一个会归零的倒计时，以便知道欢乐时光长期有效。
2. 作为限时会员，我希望资料页倒计时与我的会员剩余时间一致，以便安排钓鱼时间。
3. 作为管理员，我在后台关闭总开关后，希望玩家资料页不再显示"进行中"，以免玩家误判加成仍在生效。
4. 边界：关闭总开关再重新开启后，状态按当前资格立即恢复；非会员始终看不到倒计时；离线、重连不改变上述展示。

## Implementation Decisions

- 修改 `internal/gameserver/profilebuild.go` 中 307 档案 f24 的构造：状态枚举取 0~4，`f1` 为会话游戏分钟坐标，`f2` 为 FILETIME 哨兵 `pass745F2`。
- f24 字段语义（客户端 4.0.25034，`dlgnjgfjcaj`：f0=`mdikmdaomej` 枚举 0~4、f1=int、f2=long）：
  - 0 = 未开放（客户端文案 "Available with premium subscription" / "需要高级会员订阅"）
  - 1 = 就绪（"Ready" / "就绪"，无倒计时）
  - 2 = 下一场时间（使用 f2，本改动不下发）
  - 3 = 进行中（使用 f1 倒计时）
  - 4 = 已结束（"Is over" / "已结束"）
- 客户端倒计时公式 `[事实]`：显示分钟 = `round((f1 − 当前世界游戏分钟) / 24)`；游戏内 24 分钟等于 1 真实分钟，因此服务端写 `f1 = W + ceil(剩余秒/60) × 24`。显示分钟 > 1 时走 `kDlg_CP_HappyHour_Status_Activated`（"{0} 分钟剩余"），≤ 1 时走 `Activated2`（"剩余不到一分钟"）。
- 永久会员表示方式 `[事实]`：客户端状态机只有 0~4 五个值，本地化资源中不存在"不限时长"相关文案（`kDlg_CP_HappyHour_Status_*` 仅 Unavailable/Ready/NextTime/NextTimeInDetail/Activated/Activated2/Finished），因此没有专用状态或哨兵值可表达"不限时长"；采用状态 1（就绪、无倒计时）作为最接近且不谎报到期时间的表示。
- 总开关关闭时，有资格的玩家下发状态 4（已结束），非会员仍为 0。
- 数据与迁移：不改表、不新增迁移；`happy_hour` / `happy_hour_exp` 列保留但非真值来源，`HappyHourUnlimitedSeconds` 仅作内部/后台展示哨兵，不再进入客户端倒计时。
- 兼容与回滚：只改 307.f24 的构造分支。回滚时还原该段映射即可，无持久化数据变化、无需旧库升级。

## Testing Decisions

- 存储层：`internal/store/repos_happy_hour_test.go` 已覆盖资格计算与在线状态，不变。
- 协议层：新增 `internal/gameserver/happy_hour_test.go::TestProfile307HappyHourState`，用真实 SQLite + `BuildProfile307W` 直接断言 307.f24 的 f0/f1/f2：
  - 非会员 → 0 / 0 / `pass745F2`
  - 永久会员 → 1 / 0 / `pass745F2`
  - 限时会员（到期 now+3600s，W=1000）→ 3 / 2440 / 到期 FILETIME
  - 永久会员 + `happy_hour_enabled=0` → 4 / 0 / `pass745F2`
- 期望值来自客户端逆向结论与手算（3600 秒 = 60 分钟 × 24 = 1440 游戏分钟），不是用实现代码反算。
- 回滚后：`TestProfile307HappyHourState` 的"永久会员"与"总开关关闭"两个断言会变红（分别回到状态 3 / 状态 3），其余测试不受影响。
- 门禁：`go test ./...`、`go vet ./...`、`go build ./...`、`gofmt -l .`；欢乐时光相关用例重复运行 3 次排除时序抖动。

## Out of Scope

- 不改变加成数值、结算与资格判定逻辑（经验 +50%、咬钩 +10%、熟练度触发 +25% 保持不变）。
- 不实现官服的"每日固定时段欢乐时光"调度；本服仍是会员在线即生效。
- 不调整后台玩家详情页的"剩余时长"字段含义（永久会员仍显示内部哨兵值）。
- 不新增状态 2（下一场时间）的下发逻辑。

## Further Notes

- `[事实]` 客户端 4.0.25034 反编译：`RUIHappyHourWidget` 的 0~4 文案分支；f24 结构体仅 3 个字段；状态枚举仅 5 个值。
- `[事实]` 客户端本地化表：`Status_Activated="{0} remaining"`、`Status_Activated2="Less than a minute left"`、`Status_Ready="Ready"`、`Status_Finished="Is over"`，无“不限时长”条目。
- `[推断]` 状态 1 的图标/分隔线与状态 3 共用会员激活判断，因此"就绪"不会让玩家误以为加成关闭。
- 未验证：状态 1 在实机主页的完整视觉表现（需部署后游戏内确认）。
