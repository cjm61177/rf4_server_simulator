# 个人消息查鱼助手

Status: done

## Problem Statement

玩家需要离开游戏打开网页，才能查询指定鱼种的推荐鱼饵与位置。现有公共聊天不适合作为个人查询入口。

## Solution

在聊天玩家列表提供固定角色“查鱼助手”。玩家点击“发送消息”，直接发送鱼名，通过个人消息收到当前地图、当前时段的最多三条候选方案；也可指定地图，不提供鱼获档位筛选。

## User Stories

1. 玩家能找到查鱼联系人，直接发送鱼名或“帮助”，无需输入 `/gm`。
2. 查询回复只送达请求者，不进入公共聊天；发给普通玩家的消息不会作为查鱼指令执行。
3. 鱼名未识别、地图无此鱼或没有可行方案时返回清楚的提示；拼音前缀匹配规则见 `specs/changes/fish-query-pinyin/spec.md`。
4. 计算限定一张地图和当前时段；已核对内陆地图给出区域显示坐标范围，海图保留世界落点。其余地图明确不支持，不回退攻略点或默认点。

## Implementation Decisions

- `internal/gameserver` 新增查鱼计算和联系人入口；查询在随机取鱼前读取现有权重，复用饵效、天气、鱼群和技能计算。
- 体重模型的确定性参数与实际采样共用；计算不发鱼、不耗饵、不修改玩家数据或抽取随机数。回复使用既有邮件表持久化，并沿用请求回执防止重复回复。
- 只比较单竿、单饵及代表钓组，无窝料。显示模拟器理论条/小时，常规回复末尾仅保留“理论速率不计搏鱼、收鱼时间”；详细计算口径和限制统一放在“帮助”，不声称官服概率或全局最优方案。间隔及折算规则见 `specs/changes/fish-query-rate/spec.md`。
- 联系人仅接受“鱼名 [地图]”，不再解析星、蓝冠等后缀；计算入口固定包含该鱼种全部档位，不改变底层权重计算或生产发鱼。回复标题只显示地图和鱼种，不显示档位与查询时间。
- 内陆范围启用十七个原点、地形和纸地图标定已核对的场景，扫描边界取纸地图显示范围与 TerrainData 世界范围的交集，不二次应用地形对象的旋转或缩放。拉多加湖群岛采用场景设置引用的外层主地形作为显示原点，内层地形已被包含、不重复扫描。边界、纸地图换算与引擎依据见 `docs/fish-query-coordinates.md`。区域按生产 `fishArea` 的 40×40 世界网格划分，先剔除完全在交集外的格子、截断跨边界格子，再粗筛和配饵；不对最终获胜坐标事后挪位。原世界网格编号、分布权重和显示原点不变。聊天小数仅做显示精简并标注近似，内部边界保留精度。
- 内陆先用地图基础鱼种权重（含后台覆盖）和当前鱼群分布粗筛最多32个区域；粗筛比较目标鱼的基础权重占比，不使用鱼饵、钓法或技能，不把该评分当作最终上鱼概率。再只在入选区域比较既有单饵候选及代表钓法，按包含空口、咬饵接受率及平均间隔的目标鱼种理论条/小时排序。分布向量仅在请求内复用；粗筛可能漏掉配饵后的全图最佳组合，不承诺全局最优。
- 饵料仍使用天然饵、拟饵各最多24组的既有候选上限；本次只调整内陆筛选顺序，不扩展为全饵搜索。海图、手动坐标及关闭鱼群分布时沿用原流程。
- 区域估算不逐点计算水深、底质、水流、结构和距离；其他已启用的时段、天气、水层和生态因素仍参与。地形与纸地图范围的交集不是水域掩膜；可选五点水陆粗筛见 `specs/changes/fish-query-water/spec.md`，计算结果的 `WaterFiltered` 和 `Notes` 区分是否加载本图数据，游戏帮助统一说明限制。生产发鱼不改变；分布开关关闭时不虚构最佳区域。
- 客户端基线 `4.0.25034` 的玩家“发送消息”使用个人邮件 `19/1`，参数为目标 UID 与正文，响应 null；助手沿用 `19/10` 推送及 `19/6`、`19/7` 邮箱重读。聊天玩家列表 `24/4` 返回普通 int 数组，资料卡 `24/19` 返回 bytes 包装的 2002 对象。经 `tools/proto.ps1`、客户端方法签名和运行时类型核对；契约校验保持开启。
- 不把 `24/10` 公聊或 `24/27` 公聊广播当作私聊；不新增未核实的搜索数组类型。
- 帮助回复说明复杂地图请预留约3秒并在个人消息收取结果。保留3秒计算预算，鱼名解析和方案计算超时使用同一提示；不承诺端到端延迟，不新增查询进度邮件或改变回复时序。
- 不新增数据库表、迁移、管理权限或客户端文件。角色为服务端虚拟联系人，不写成玩家账号。
- 不接收发给虚拟角色的物品。回滚为更换原程序，玩家数据无需转换，已生成的文本回复仍保留在收件箱。

## Testing Decisions

- 纯计算：手算候选权重与概率样例；查询与实际采样对照；查询不消耗生产随机数。
- SQLite：指定地图、饵料短名单、名称解析、坐标来源，以及查询前后玩家库内容一致。
- 区域：竞争权重手算、偏移场景裁剪后批量结果与逐格生产权重对照、全部支持地图的交集面积和逐格边界、苏拉河仍覆盖 400 格、克马羚诺也湖 121 格及铜湖 64 格的查询和首尾裁剪、群岛 5776 格无重复覆盖及外层原点显示换算、纸地图内部/外扩/整格对齐/空交集、非法标定、负原点首尾格截断与世界网格对齐、原分布权重保持不变、非法原点及格数上限、未知地图明确拒绝、分布关闭、取消及空结果；只读数据库和生产随机数保持不变，生产点生态不受影响，原海图查询继续使用候选落点。
- 协议回环：固定角色可发现、个人消息发送接收形状、回复先应答后推送、隔离和重放；普通玩家寄件沿用既有测试，物品不能寄给助手。
- 回复文本：帮助只说明鱼名及可选地图，保留等待时长及接收方式；当前图、指定图及查询前缀可用，旧档位参数不再作为过滤条件。标题不含档位及查询时间，空结果不虚构地图；已过期计算上下文在鱼名解析阶段也返回超时提示，不误报资料不可用。
- 两阶段查询：粗筛基于无饵基础权重且保留固定上限；同分稳定、零权重及后台覆盖处理正确；配饵后不回到落选区域，最终按理论条/小时而非粗筛评分或条件概率排序。核对全图扫描数与精算区域数，保留只读、不耗随机数及未支持地图、海图回归。
- 执行完整 `go test ./...`、`go vet ./...`、`go build ./...`。实机验收玩家列表入口、发送鱼名及指定地图、重新打开收件箱。
- 删除查询入口或误用公聊会使相应回环测试失败；改变实际权重或误触随机数会使计算测试失败。

## Out of Scope

发物品、GM 管理、好鱼保护、过滤、倍率、重放、全天全地图搜索、网页或外部查询 API、其他未核对地图的坐标适配、精确地形可达性筛选和逐落点最优解。离线水陆粗筛由独立的 `fish-query-water` spec 描述。

## Further Notes

- [事实] 主干已有鱼种名册、饵效与海图数据，以及实际判鱼计算；玩家菜单的发送消息使用个人邮件接口。
- 计算仅比较当前时段的有限候选，不保证全局最优。装备限重关闭时使用永久技能，不计竿体加成；开启时使用手持竿及其可用钓组。
- 实机验证：联系人入口和原始查询回复已确认正常；区域查询、入口精简及纸地图裁剪的自动测试不代替实机验收。纸地图范围依据当前客户端离线数值资源与显示换算调用点核对，不将其写成游戏内逐图验证结果。
- 坐标依据：当前客户端底钓位置接口、公共抛竿对象构造及序列化调用链已与运行时世界位置核对；不是新增原始报文采集，也不扩大为全部钓组、全部地图的实机验收。
- 自动验证：`TestFishQuery*` 覆盖实际抽样对照、只读计算、不耗随机数、成员列表、个人消息协议与重放，以及区域粗筛、排名、边界、拒绝未支持地图和海图回归。`BenchmarkFishQueryRegionalGrid` 覆盖60鱼种、1444区域粗筛至32区域，再比较72组方案；性能结果依机器和静态资料而异，不承诺固定延迟。
- 当前区域实现通过完整 `go test ./... -count=1 -timeout=180s`、`go vet ./...`、`go build ./...`；这些自动结果不代替尚未完成的区域实机验收。
