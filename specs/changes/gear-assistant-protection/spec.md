# 钓具助手与满红不爆

Status: done (implementation and automated checks); client validation pending

## Problem

玩家希望通过固定虚拟联系人的个人消息切换满红不爆，不输入 GM 前缀，也不连带开启跑鱼回放或免除普通磨损。

## Solution

玩家列表增加“钓具助手”，只支持满红不爆。发送“开/开启”“关/关闭”“状态”“菜单/帮助”；未识别文本返回当前状态和菜单，不修改设置。默认关闭，按玩家保存，作用于该玩家所有鱼竿。

## User Stories

- 在线发送“开”后，后续装备断件上报被取消，正在搏鱼的竿和鱼不变；关闭后恢复原规则。
- 锁轮过载不累计烧毁与过载应力；普通钓获、使用、泡水和未锁轮泄力打滑磨损保留。
- 重复开启不反转开关，重登保留设置，回复只发给操作玩家。
- 主动剪线、自然脱钩、原有鱼口与结算不改变，已发生损伤不修复。

## Implementation Decisions

- 复用现有查鱼联系人的资料卡、个人消息与回执机制，不建立真实账号或授予管理员权限。
- 客户端基线 `4.0.25034`。沿用 `24/4` 普通 u32 数组、`24/19` bytes 包装 2002、`19/1` null 应答和 `19/10` args(524)[11062]；依据见 `docs/debugging-workflow.md` 的已确认协议事实。不修改响应形状与合同。
- `17/9` 经 `tools/proto.ps1` 核对成功响应为 11028；保护时不伪造断件成功，沿用既有失败信封 `System.OperationCanceledException` 取消客户端破坏操作。客户端失败路径能否持续搏鱼仍需本轮实机回归。
- `kv` 保存独立的玩家布尔设置，开关和回复邮件在同一事务中提交，不新增表或改动静态库。读取失败不当作关闭而执行破坏。
- 先验证断件上报和装备归属，再检查保护；取消时不结算断件冲击、不扣线、不拆装备、不清鱼、不安排重推或推送装备更新。
- 仅在负载计账入口抑制受保护的锁轮过载增量；未保护期间已产生的账保留。切换时重置各竿过载段与采样时间，关闭后不补记保护期间的损耗。开关写入与断件/负载入口互斥，使成功回复后的操作读取新值。

## Testing Decisions

- 临时 SQLite 与真实分发器：默认值、开关幂等、事务回滚、重连读取、玩家隔离、资料卡、邮件应答/推送顺序和回执重放。
- 多竿装备破坏取消、鱼 GUID 保持、无装备更新或损伤日志、归属检查、关闭后恢复损坏。
- 锁轮计账抑制、切换后的时长、保护前损耗保留、普通打滑与使用磨损保留、主动剪线和自然脱钩不被保护。
- 本次修改后执行完整 `go test ./...`、`go vet ./...`、`go build ./...`。如遇已披露的 `TestFishMarketFlow` 间歇失败，如实记录，不修改它来使门禁变绿。
- 实机待验收：开关回复与重登；多竿满红连续搏鱼；关闭恢复规则；自然脱钩和主动剪线。

验证结果：更新到已合入查鱼的主干后，钓具助手、查鱼、渔轮计账与嘬饵专项连续3轮通过（19.753秒）；完整 `go test ./... -count=1 -timeout=300s` 通过（gameserver 82.421秒），`go vet ./...`、`go build ./...` 通过；水陆预处理的6项合成测试通过。保留上游的鱼拉力公斤力换算、每竿基准去重和路亚基准折扣。本轮未复现先前披露的上游间歇失败，不代表该问题已修复。使用临时测试库与本机回环连接，未启动真实游戏、未部署；客户端持续满红搏鱼仍待实机验收。

## Out of Scope

无跑鱼回放、鱼口倍率、鱼种过滤、免除所有磨损、装备修复、后台界面或客户端改动；不部署或推送。
