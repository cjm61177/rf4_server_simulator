# 修复拟饵内嵌钩断件被拒绝

Status: done

## Problem Statement

拟饵出厂钩没有独立 `item` 行，客户端在满力度断钩时通过 `17/9` 上报拟饵树里的
内嵌 hook GUID。服务端旧校验只扫描竿树前三个出厂槽位，找不到该 GUID 就返回
`sql: no rows in result set`，导致断件不落地，玩家看到力度条满但装备不断。

实机日志已连续出现同一配置（`spin_10158_M100HH` + `spin_5691`）的 `17/9`
处理失败，登录和装备归属均正常。

## Solution

- `validateBreakReport` 遇到非独立物品 GUID 时，改为检查该 GUID 是否属于当前竿
  或挂在该竿上的组件子物品树。
- 除竿本体树外，扫描 `rig_component` 中挂载物品的完整树，并补扫已挂拟饵。
- 校验仍要求母竿和挂载物品属于当前玩家，不接受别的竿或未装配物品的 GUID。
- 通过校验后继续走既有最弱环/终端件裁决：拟饵出厂钩断掉时移除整只拟饵，
  不损坏竿、线或轮。

## Testing Decisions

- 使用截图配置的同类真实定义：`spin_10158_M100HH`、`spin_5691`、
  `braid_40898`、`leader_crafted_60`、`plug_w_2370`。
- 从拟饵树中取内嵌 hook GUID，调用生产断件校验与处理入口。
- 断言校验通过、拟饵被删除、鱼竿耐久不变。
- 既有出厂竿件、外置钩、终端件和跨竿伪造测试继续通过。

## Out of Scope

- 不改变客户端断件触发条件或物理强度公式。
- 不改变拟饵出厂钩的定义与数值。
- 不调整钓具助手“满红不爆”开关。
