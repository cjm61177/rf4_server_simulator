# 鱼种体长系数校准

Status: done

## Problem Statement

同重量下不同鱼种的模型尺寸几乎一样：狗鱼不够细长、鳊鱼不够短厚、鳟鱼与鲶鱼看起来没差别。
玩家按重量判断"这是条大鱼"时，画面上得到的体型与鱼种常识不符，鱼种辨识度被削弱。

根因不是模型缩放，而是体长换算系数：客户端 `27.f3` 直接取
`LengthM = length_k × W(g)^length_p`，而静态库 `species_weight` 里 252 个鱼种有 248 个
共用同一个默认 `length_k`。

## Solution

按"现实最大体长 ÷ 站点记录最大重量的立方根"重算系数，让同重量的不同鱼种呈现各自的体型比例。
校准以查表覆盖的方式生效，静态库本身不变。

## User Stories

1. 作为玩家，我希望同重量的狗鱼比鲤明显更长更细，重型鱼看起来符合该鱼种的真实体型。
2. 边界：未收录的鱼种（含蟹、鱿、蚌、蛙等非鱼类）继续使用静态库原值，行为与改动前一致。
3. 边界：重启、换图、重连后系数稳定，不随会话变化。

## Implementation Decisions

- 模块：`internal/gameserver`（判鱼时读取体长系数、构造 `27` 鱼对象）。
- 接口：无协议改动。`27.f3` 仍为长度（米），字段语义与取值范围不变。
- 数据与迁移：**不改表结构、不写迁移、不改 `server_data/static.sqlite3`**；
  校准值以内置查表覆盖，未命中回退静态库原值。因此静态导入的内容哈希保持稳定，
  已有存档与新库都无需升级动作。
- 校准方法：`length_k = 现实最大体长(m) ÷ 站点记录最大重量(g)^(1/3)`，新增校准项的 `length_p` 固定 1/3；
  重量锚点取 `cn.rf4-stat.com` 各鱼种历史最大重量，体长锚点取现实生物学最大体长；
  缺少站点重量的鱼种用已锚定样本回归后夹在 `[0.02, 0.09]`。
- 只覆盖静态库仍使用默认 `k=0.0355`、`p=1/3` 的鱼种。静态库已有的非默认 `k` 或 `p` 是官方样本标定曲线，必须原样保留。
- 正常判鱼、内置鱼池回退、管理端补录/指定鱼和交易卡初始化统一走同一个 `calibratedLengthKP`，避免同一鱼种因生成路径不同得到不同体长。
- 蟹、鱿、蚌、蛙等非鱼类不参与校准。
- 兼容：客户端基线 4.0.25034；回滚方式为删除查表条目或整体回退该文件。

## Testing Decisions

- 测哪一层：单元（查表与换算逻辑，无 DB、无网络）。
- 期望值来源：常量算例与已知锚点——`0.0655 × 5000^(1/3) ≈ 1.12 m`（狗鱼）、
  `0.0442 × 5000^(1/3) ≈ 0.75 m`（鲤）。
- 覆盖的用例：校准命中、狗鱼系数大于鲤、两者 5kg 显示长度落在现实区间、已有官方曲线保持原值、非鱼类和未收录鱼种原样返回、DB 查询与缓存两条路径均应用校准。
- 回滚后哪些测试会变红：删除查表后 `TestCalibratedLengthKP` 的校准断言和 `TestCachedSpeciesLengthKPAppliesCalibration` 的 carp 断言会失败。

## Out of Scope

- 不改重量分布、档位线（上星/上蓝）与结算。
- 不改鱼模型网格、材质与玩家可见的其他尺寸（竿、护网等）。
- 不提交静态库二进制，也不改其内容。
