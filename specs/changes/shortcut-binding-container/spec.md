# 快捷栏绑定随容器移动保留

Status: done

## Problem Statement

竿子从背包移到帐篷、车、船、滑板车或房子后，快捷栏绑定会被清掉。客户端按返回列表重新编号，表现为快捷栏槽位错位。保存快捷栏时还把背包、装备架以外的容器当作不可用，导致已有绑定无法随整组快捷栏一起保存。

## Solution

快捷栏绑定只在物品转移给其他角色、删除，或进入鱼护、导入的原生容器时清除；在背包、装备架、帐篷、车、船、滑板车和房子之间移动时保留。整组保存也能接受这些受支持容器里的已有绑定。

## User Stories

1. 作为玩家，我希望把竿子放进帐篷、载具或房子后，快捷栏槽位保持不变。
2. 边界：鱼护和导入的原生容器仍会清绑定；物品归属变化或删除时绑定也必须失效。

## Implementation Decisions

- `internal/store/migrations` 追加迁移，替换容器移动清理触发器，使受支持容器之间移动不删除绑定。
- `internal/store/repos_shortcut_alias.go` 的可用性判断与触发器使用同一容器集合。
- 数据与迁移：新增后续迁移，不改已发布迁移；旧库启动时按正常迁移流程升级。
- 兼容：不改变协议；回滚方式为 revert 本 PR 提交。迁移回滚需恢复旧触发器并清理本次迁移记录。

## Testing Decisions

- 存储层使用真实 SQLite 和完整迁移。
- 覆盖绑定物品在 backpack、rig、tent、car、boat、scooter、house 之间移动后仍保留。
- 覆盖已有绑定移到 tent 后，再绑定另一个背包物品时整次保存成功。
- 覆盖 keepnet、`native:*`、删除和角色归属变化仍清绑定；回滚对应修复后新增断言会变红。

## Out of Scope

不改变快捷栏协议、槽位编号规则或其他物品容器语义。

## Further Notes

`[事实]` 客户端按服务端返回的快捷栏列表顺序编号，绑定丢失会造成槽位错位。
